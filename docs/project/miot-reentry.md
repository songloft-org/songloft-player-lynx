## 已确认的机制

客户端基线 `b952231c253aad1938d3020ee74157b100a11291`，插件基线 `6fba93e6f3bdb4e73c00a9a58da67475cd0519d1`。本批为未提交工作树，保留既有桌面候选及父仓库改动。源码摘要和检查结果在 `/tmp/songloft-miot-reentry/verification.json`。

首页网格进入 `/plugin/miot` 时没有 `tab=true`，原 `RetainedPluginTabs` 只保留导航 Tab 的原生 frame。返回首页便卸载页面与子引擎，再进入必然重建。修复后所有原生 Lynx 插件入口由稳定 Shell 持有同一实例；路由页面只提供首页/管理入口的标题栏。保留区域在标题栏下参与 flex 布局，不覆盖标题栏，也不重复计算 Shell 已提供的顶部安全区。首页和 Tab 共用实例，并分别更新 embed；离开路由时保留其最后的展示方式。停用、插件版本/更新时间变化、服务器切换及 Shell 退出沿用既有释放机制。

用户补充 Tab 中仍会闪封面后，发现 miot 的 `Cover` 每次收到 resumed 都增加 nonce、清空 source、更换 image key，并为本地 URL 添加 `_r`。因此插件实例未重建也会强制重载所有封面。插件改为只恢复失败/超时图片，成功图片及正在排队/加载的任务保持不变；保留两次自动重试、下次恢复重试和不改写 data/签名 URL 的行为。插件侧证据同步于其 `docs/lynx-migration.md`。

反复创建子引擎和强制重载图片会增加不必要的工作，但本批没有鸿蒙崩溃堆栈、设备内存记录或设备复现，**不能据此确认闪退是 OOM、SDK 销毁竞态或已被修复**。需要客户端/系统版本和崩溃日志继续核对。旧白屏问题及必须更新原生壳的范围另见 [Harmony 插件容器](harmony-plugin-frame.md)。本批没有修改 ArkTS/Kotlin/Swift。
