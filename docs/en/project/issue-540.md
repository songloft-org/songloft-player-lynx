## Cause and fix

- While pagination/layout was pending, the thumb always used `currentIndex`, initially 0. The destination was stored, but the thumb returned to the first song. It now displays the requested position while pending; the song hint still describes visible rows.
- Native `scrollToPosition` cleared the request immediately and again on success. Receiving data does not mean native rows have been laid out, and successful invocation does not prove visibility. Native and Web now both wait for visible-row confirmation, using the existing 200ms retry interval and maximum of 25 attempts. Errors, timeouts, empty pages and unmount cannot retry indefinitely. The invocation checks the request generation to reject stale seeks.
- During rapid dragging, list-end and seek signals can call `fetchNextPage` before state updates, canceling and restarting the same page by default. `cancelRefetch: false` makes overlapping signals reuse the active page request, with a new page-level regression covering this contract.
- Sorting, backend APIs, normal paged loading and the playback queue are unchanged.
